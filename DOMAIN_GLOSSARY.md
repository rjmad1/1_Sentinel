# Sentinel (EIIP) Domain Glossary

## Domain Entities & Hierarchy
- **Tenant**: The high-level isolation boundary for an enterprise or organization.
- **Site**: A physical or logical location grouping multiple machines (e.g., a specific data center, regional office, or developer workspace).
- **Machine**: An individual hardware unit (workstation, server, VM) running the Sentinel collector.
- **Asset**: A physical hardware component (CPU, RAM, storage) or software package (Chocolatey/Winget package, WSL container).
- **Application**: A user-facing executable or library package installed on a Machine.
- **Service**: A background task or daemon managed by the operating system (e.g., systemd service, Windows service).
- **Process**: An active execution instance of an application running on a Machine.
- **Port**: A logical network endpoint used by a Process to communicate.

## Topology Graph Terminology
- **Node**: A vertex representing an entity (e.g., `Machine`, `Service`, `Process`, `Container`, `Network`).
- **Edge / Relationship**: A directed link representing relationships between nodes:
  - `HOSTS`: A Site/Machine hosts resources or services.
  - `RUNS`: A Machine or Operating System runs a Process or Service.
  - `DEPENDS_ON`: A software package or process depends on another software package or process.
  - `USES`: A Process or Service uses system resources or libraries.
  - `CONNECTS_TO`: A Process connects to another Process or remote port.
  - `EXPOSES` / `LISTENS_ON`: A Process exposes a specific Port.

## Assessment & Intelligence Terminology
- **Finding**: An alert, vulnerability, configuration drift, or lifecycle warning generated by the Assessment Engine.
- **Severity**: The level of critical impact of a Finding (e.g., Critical, High, Medium, Low).
- **Confidence**: The probability score indicating the certainty of a Finding.
- **Risk**: A calculated threat score summarizing multiple Findings to represent overall system operational hazard.
- **Forecast**: Predictive calculation estimating resource exhaustion timelines (e.g., storage capacity limits in 30/90 days).
- **Remediation**: An automated or manual fix plan generated to resolve one or more Findings.
- **Validation**: Post-remediation health metrics collection used to confirm the corrective actions succeeded.
- **CloudEvents**: Standardized JSON envelope specification used for publishing/subscribing to events over the NATS message broker.
- **InsForge**: Open-source BaaS backend hosting the SQL/NoSQL storage, authentication layers, and workflow orchestrations.
